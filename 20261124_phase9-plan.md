# Phase 9 plan: what the analysis after phase 8 found

Plan · 2026-11-24 · for the shared UI spec, `20261122_ui-concept.md`

Phase 8 finished the migration table. The analysis that followed it checked the spec section by section against both repos. What it found falls into three kinds:

- deviations to fix in the code;
- deviations where the code is right and the spec should say so;
- code both apps still copy outside `packages/`: about 2,400 identical lines, which the spec never planned for.

This plan closes those, in six parts. The decisions below come first because some parts depend on them.

## How every part is done

- Shared changes land in mdviewer-mj first. Agent MCR takes them with `git subtree merge`, then makes its own changes. Each part is committed in both repos.
- `npm test`, `tsc -p .`, `tsc -p packages` and `npm run build` pass in both apps.
- A part that should not change the look is checked with the computed style of every element, before and after, in both themes and both apps. The states are: document, find, edit, split, tab menu, settings, plain text, contents, Journal, Live, Board, the palette, keys pressed, and a memory window. The tool for this is the preview page in each repo's `preview/` folder.
- A part that changes the look on purpose comes with before and after screenshots for review.
- At the end, the spec's phase 9 row says what was done, what changed on the way, and what was not done.

## Decisions first

Each has a recommendation. Mark the one you choose.

- [x] **D1 Toolbar button size.** The spec says 28 px; the Documents bar, the spec's reference look, has 24 px in both apps. *Recommended:* change the spec to 24 px. **Chosen** (with part 1): 24 px.
- [ ] **D2 Focus line.** The spec asks for a 1 px `--focus` line on every focused pane's header. Today it is a 2 px `--accent` line, drawn only for document groups, journal details and Live panes, and only when there are several. *Recommended:* one workbench rule, the 2 px accent line on the focused pane's header in every layout, so F6 always shows where it went; change the spec to match.
- [ ] **D3 Agent documents.** The spec calls them Agent MCR-only, but MDViewer has them too. `AgentPanel.tsx` (176 identical lines) and `utils/agent.ts` (77) are copied. *Recommended:* make them a shared feature package (part 4).
- [x] **D4 Live's layout.** §7 planned to move Live onto a stored workbench layout. Live still keeps its own split tree (`paneLayout.ts`, the `hs-list-width` key), which the workbench's `LayoutView` already draws. *Recommended:* don't move it. It works, and `LiveWorkspace.tsx` changes often on Agent MCR's `main`. Record it in the spec. **Chosen** (with part 1): Live keeps its tree.
- [x] **D5 Commands as a plugin point.** *Recommended:* keep each app's menu as its own list (`buildMenu`), as decided in phase 8, and record that in §5.5. Give the workbench the window commands both apps define identically (part 2). **Chosen** (with part 1): each app keeps its list.
- [ ] **D6 One palette with providers (§5.5).** MDViewer's palette lists tabs, files and commands. Agent MCR's lists sessions, with filters and a preview. *Recommended:* yes, in part 5, after the parts that are cheaper and remove more copying.

## Part 2. One copy of the window parts both apps copy (medium)

Only the palette button is new on screen.

- [x] **Top bar end (§5.1).** The workbench draws Palette, Settings and Theme at the right end of the bar from what `Workbench` already gets (`settings`, `appearance`), plus `onPalette`. Both apps' identical `ToolbarEnd` go. The palette button is new in both.
- [x] **Window commands.** The workbench provides Command Palette, Settings, Dark Theme, Light Theme and Pin Status Bar (`windowCommands`). Both apps define these five identically today.
- [x] **Document zoom control.** The identical `ZoomControl` becomes the reader's (`DocumentZoom`), and both toolbars use it.
- [x] **Base element CSS** into `ui.css`, before every app's CSS: the 15 identical rules (resets, scrollbars, `::selection`, `:focus-visible`, button/input/link resets). Agent MCR keeps these in `@layer base`, MDViewer doesn't. The layer decides how they lose to other rules, so choose one and compare both apps' computed styles.
- [x] **Unsaved-edits guard.** The close-window guard becomes a `readerPlugin` option (`confirmClose`: the app passes its window's close event and its name). Both `App.tsx` drop their copy.

**Done when** computed styles are identical apart from the palette button, and the identical lines between the apps' `Toolbar.tsx`, `commands.ts`, `App.tsx` and `index.css` are gone.

Done 2026-11-24. The `Workbench` draws ⌕, ⚙ and ☾/☀ from its `palette`, `settings` (now `{ open, onOpenChange }`) and `appearance`, with tooltips from the commands (`commandTitle`: "Settings (Ctrl+,)"). The palette button is new in both apps; Agent MCR's is disabled outside Sessions, where its command panel isn't hosted. `windowCommands` makes the five commands, and Agent MCR takes its palette key from the workbench. The scrollbar colours and `color-scheme` are tokens now. `confirmClose` takes the window's close requests from each app's `onWindowCloseRequested`, which is Tauri, so it stays in `utils/tauri.ts`.

- Each store has `setTheme` in place of the `toggleTheme` that App and the commands both wrapped.
- Tooltips at the bar's end now open leftwards: the theme button's was cut off at the window's edge.
- Unused variables went: `--danger-hover-bg` and `--panel-default-width` in both apps, `--drop-overlay-bg` in Agent MCR.

## Part 3. The look, finished (§4.2; medium, visible)

- [ ] **Focus line** as decided in D2, as one workbench rule for every `LayoutView`. The reader's, the journal's and Live's own focus rules go.
- [ ] **Tooltips name the shortcut**, taken from the command list (a workbench helper that gives a command's title with its key). This covers the toolbar buttons that don't yet: Files (Ctrl+B), History (Ctrl+H), Contents (Ctrl+Shift+O), zoom, split.
- [ ] **Live's list gets the 40 px pane header** ("Sessions", with its tools). Do it as one small change to `LiveWorkspace.tsx`, right after merging Agent MCR's `main`.
- [ ] **Agent MCR's Live, Board, Slack and Cockpit:** their 56 raw buttons become `Button`. Ghost in panes and rows; primary or secondary only in forms and dialogs. Their button rules in `harness.css` and `index.css` go.

**Done when** screenshots of Documents, Journal, Live, Board and Slack in both themes are reviewed, and no pane has a bordered text button left.

## Part 4. Agent documents as a shared feature (large; if D3 says so)

- [ ] **`@lambda-house/agents`** (layer 3, beside reader and journal), added to `layers.test.ts`. It holds the panel (what both `AgentPanel.tsx` share), the entry model and grouping (what both `utils/agent.ts` share), an `AgentHost` (scan, change events, mark read, read snapshot) and `agentsPlugin`. MDViewer shows the panel inside Files; Agent MCR shows it as its own `agent-docs` pane.
- [ ] **The agent-file refresh** (scan on change, poll when unwatched, on window focus) moves out of both `App.tsx` into the plugin, with a condition for when it runs.
- [ ] **Read tracking** (`changes` in `ReaderHost`) reads the agents' state from the plugin rather than each app's store.

**Done when** what remains of `AgentPanel.tsx` and `utils/agent.ts` in each app is only its own, and computed styles are identical.

## Part 5. The plugin points still missing (§5.2, §5.5, §5.6; medium to large)

- [ ] **`workbench:view`.** A surface's views (id, label, icon, order, `keepMounted`, render, tools) come from the registry, and `ShellViews` draws them. Agent MCR's Sessions views (Live, Journal, Board, Slack, and plugin tabs through `sessions:top-tab`) are contributed there.
- [ ] **Status items get an `id` and an `order`.** The bar sorts by `order` rather than the order things render.
- [ ] **One palette** (D6): `workbench:palette-provider` (`id`, `label`, `search(query, signal)`), drawn by the `Workbench`. The commands are one provider. MDViewer adds open tabs and files, Agent MCR its sessions, filters and preview. Both apps' palette components go.

**Done when** both palettes list what they listed before, there are tests for providers and view contributions, and computed styles are identical.

- [ ] **Journal panes zoom:** list and detail, Ctrl+wheel, the header badge.
- [ ] **The toolbar's zoom shows the focused pane's zoom** (§5.4), or the spec records that it is the document's.

**Done when** the tests pass and screenshots of a narrow window are reviewed.

## Not planned (recorded in the spec)

- `WorkbenchHost` (§5.8): left out on purpose in phase 6.
- Commands as a plugin point (D5) and Live's own tree (D4).
- Moving the window state (theme, surface, status bar, Settings and palette open) out of the app stores into the workbench. The 10 identical store members don't justify a migration of saved state.
- The Tauri adapters (`utils/tauri.ts`, 270 identical lines): packages never import Tauri, so each app keeps its own.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

MDViewer is a cross-platform markdown document viewer built with Tauri 2.0, React 18, and TypeScript. It renders markdown with Shiki syntax highlighting, Mermaid diagram support, and features a tabbed multi-document interface.

## Build Commands

```bash
npm install              # Install dependencies
npm run dev              # Start Vite dev server (port 1420)
npm run tauri dev        # Run full Tauri desktop app in dev mode
npm run build            # TypeScript check (app, then packages/) + Vite build
npm test                 # Frontend unit tests (Vitest)
npm run tauri build      # Build production desktop app
```

Frontend unit tests are Vitest files next to the code (`src/utils/*.test.ts`; DOM tests declare `// @vitest-environment happy-dom`). There is no linter. The Rust backend has unit tests: `cd src-tauri && cargo test`.

## Architecture

### Frontend (src/)

- **State Management**: three Zustand stores with localStorage persistence
  - `src/store/index.ts` (`useStore`, key `mdviewer-storage`): file tree, the Documents layout (`documentsLayout`, rules in `store/documentsLayout.ts`: Files, Search and History take turns in the left panel, Files comes back as it was when Search or History hides; `showPanel`/`hidePanel`/`togglePanel`, read with `panelShown`), `panelZoom` of Files and Contents, workspaces, search panel, theme, app settings. It follows the reader: the file tree selects the focused group's document, and the reader gets the theme
  - `src/reader.ts` (`useReader`, key `mdviewer-reader`): the reader store of `@lambda-house/reader` (`createReaderStore`): open documents, document groups (tabs, back/forward, zoom, find, headings) and their arrangement (`layout`, a workbench layout of `documents` panes keyed by group id), the focused group, recently closed, scroll positions per group and document, edit mode, the reader settings (smooth scrolling, remote images, text colours, language aliases, find options). Constants (`MIN_ZOOM = 50`, `MAX_ZOOM = 1600`, `MAX_RECENT_CLOSED = 10`) are the reader's. On its first run it takes the tabs, zoom and settings over from the old `mdviewer-storage` (version < 5); the app store imports `reader.ts` first so that happens before it rewrites its own (`src/reader.test.ts`). `reader.ts` must not import anything that imports the store
  - `src/agents.ts`: the agent documents of `@lambda-house/agents` (`createAgents`: the last scan, not saved) and their host (Tauri: the agent workspace, its change events, mark read, read snapshots; a document opened for a look goes into the history). `agentsPlugin` (registered in `App.tsx`) scans them while the global root is on or one is open, on every change and when the window gets the focus, polls when the backend can't watch, and scans again when the opened folders change
  - `src/readerHost.ts`: the reader's host (Tauri: files, the save dialog, links, reveal in folder; agent documents' read tracking through `agentChanges(agents)`) and `openPath`, which opens a file in the focused group, selects it in the tree and logs it in the history. `reader` (store + host) goes to `ReaderProvider` around the app
  - `src/journal.ts` (key `mdviewer-journal`): the journal store of `@lambda-house/journal` (`createJournalStore`: the index snapshot, not saved; the layout of list and detail panes, each list's filters, each detail pane's session and tab) and its host; `journal` goes to `JournalProvider` around the Journal surface. A memory window keeps nothing

- **Components** (`src/components/`):
  - `App.tsx` - Assembles the window from plugins (shared UI spec §3.3): it registers `readerPlugin`, `journalPlugin` (not in a memory window) and MDViewer's `documentsPlugin` in the registry of `src/workbench.ts`, and draws the workbench's `Workbench` of them: one top bar (the Documents/Journal switch, the main menu, the shown surface's tools, then the Workbench's palette, settings and theme buttons, from its `palette`, `settings` and `appearance`) over the surfaces, the Settings dialog of their tabs, their overlays inside their wrappers; the menu's keys and the native menu's events run its commands there. The rest of App is the Tauri side: scanning and watching the opened folders, agent files, drops and launch paths (`opening.ts`: Open File/Folder too), the update check. Closing with unsaved edits asks first: the reader's `confirmClose`, which gets the window's close requests from `onWindowCloseRequested` (`utils/tauri.ts`)
  - `documents.tsx` - MDViewer's plugin: the Documents surface (mounted only while shown; the Journal stays mounted once opened, a memory window has Documents only): the toolbar, the update banner, and a `LayoutView` of the store's `documentsLayout` whose pane types are what plugins bring for the `documents` view (`usePaneTypes`): the left panel's `files`, `search` and `history` from here (switchable: a pane's title is a type menu), `documents` and `contents` from the reader. Handles and the pane menus (⋯: split, join, swap, close) change the layout through `setDocumentsLayout`, which takes only layouts MDViewer can draw. A window too small for the panes draws them fitted, never saved (the workbench's `fitLayout`: Contents gives way first, then Files; side panels shrink towards their minimums); a squeezed pane's handle shows it again (`revealLeaf`, which collapses the other in the stored layout). Each pane type's `zoom` is how Ctrl+wheel over it zooms (Files and Contents: `panelZoom`, `zoomOf`). Also the Folders and Updates tabs and the palette
  - `MainMenu` (from `@lambda-house/workbench`) - Toolbar menu (top left): every command, grouped, with its shortcut
  - `CommandPalette.tsx` - Ctrl+Shift+P (⇧⌘P): the workbench `Palette` with open tabs, files of the opened folders and the commands
  - `FilePanel.tsx` - Left sidebar file tree browser
  - `DocumentGroups` (`@lambda-house/reader`) - The documents pane: the reader's groups side by side or above each other (its own `LayoutView`, groups kept alive). `splitGroup` (Ctrl+\, the tab bar's split button) opens the focused group's document in a new group at its zoom and scroll; a group goes when its last tab closes (not the last group); `closeGroup` refuses the only copy of unsaved changes. Commands, the toolbar, contents, status bar, find, save and export act on the focused group; Ctrl+wheel zooms the group under the cursor (the group pane type's zoom). A file shown in two groups is edited in one (`editorGroupFor`: the focused one if it shows it). Find's two highlight objects show every group's matches. A workspace loads into one group
  - `DocumentPanel` (`@lambda-house/reader`, `packages/reader/src/DocumentPanel.tsx`) - A document group: its tab bar (preview tab, context menu, back/forward, overflow scrolling), find bar, the rendered document with ErrorBoundary, and the editor. Scroll positions are anchored to the block at the top of the view (`scrollAnchor.ts`), so late Mermaid output doesn't move the restored text. It handles the links in its document (anchors, the browser for web links, local files through the host's `followLocalLink` and `openPath`, resolved against the clicked document). `readerPlugin` gets `empty` (what to do when no document is open) and draws `SaveAllDialog` and `CloseDocumentDialog` once; it also reads the saved tabs back (`restore`), opens a memory window's document (`windowDocument`), asks before the window closes with unsaved edits (`confirmClose`), and does Mod+1…9 and the mouse's side buttons
  - `Contents` (`@lambda-house/reader`) - The contents pane on the right: the focused group's headings; a click scrolls in that group. Its sizes are the reader's (`CONTENTS_*_WIDTH`), its zoom the pane type's (`usePaneZoom`); App passes `onClose` (hide it, as the toolbar does)
  - `AgentPanel.tsx` - The global agent files: a root inside Files (folded until opened), its header and actions; the list in it is `AgentList` from `@lambda-house/agents`, of the agents' own documents (a project's are in its folder's tree, Files → Agents)
  - Find bar (the reader's `FindBar.tsx`) - Ctrl+F find in document, per group (CSS Custom Highlight API; highlights are changed in place, WebKitGTK doesn't repaint replaced ones). A jump and the scroll restore both use `holdScroll` (`@lambda-house/reader`) to keep their offset while late output changes the layout
  - `SearchPanel.tsx` - Ctrl+Shift+F text search in open tabs / folders
  - Editor (the reader's `Editor.tsx`) - CodeMirror 6 source editor (Ctrl+E), lazy-loaded; per-document state lives in `editorRegistry.ts`, saving and export in the reader's `save.ts` / `export.ts` (`saveActiveDocument(reader)`, `exportActiveDocument(reader, format)`)
  - `WorkspaceMenu.tsx` - Saved workspaces (folders, tabs and the Documents layout; one saved before it had a layout keeps the current one): the shared `Menu` of the saved ones (a check on the current one) with Save, Detach, "Save current as…" and "Delete a workspace…", the last two in a `Dialog`
  - `Toolbar.tsx` - The Documents tools in the top bar, put there with `ShellTools` (search, panels, the reader's `DocumentZoom`, contents), as the workbench's `wb-tool` buttons in `wb-tool-group`s; the palette, settings and theme after them are the Workbench's, on every surface. The `Workbench`'s `titleBar` (`native` by default; Agent MCR's macOS window is `overlay`) makes the bar the window's title bar: room for the traffic lights, and only the bar's own empty space drags (the Shell marks what goes into it `NO_DRAG`). A surface's tools go into the bar the same way from anywhere in its tree (the journal's `JournalView` does it for Refresh, Connections, User memories, Agent access and the summary; `.sc-bar` gives them the journal's type, since they render outside `.session-cockpit`)
  - Shared controls come from `@lambda-house/ui` (`packages/ui`): `Button`, `ConfirmDialog` (buttons in the platform's order; the reader's `SaveAllDialog` and `CloseDocumentDialog` use it), `Dialog`, `SplitHandle` (separators: drag to resize, drag to the edge or double-click to hide/show, arrows step), `Segmented` (the Files/Agents filter; the Shell's surface switch uses it too), `Tabs`, `Menu` (the tab context menu, the workspaces menu), `PaneFrame` (a pane header; Files, Search, History and Contents use the workbench's `Pane`, which adds the type menu, the zoom badge and the pane menu), `EmptyState`, `Kbd`, `Badge`, `Notice`.
  - Settings: the workbench's `SettingsDialog` (Agent MCR's layout), one dialog of registered tabs: the workbench's (`appearanceTab`, `shortcutsTab`), the reader's (`readerSettingsTab`: smooth scrolling, remote images, text colours, language aliases), the journal's (`journalSettingsTabs`: session and agent access, memories) and MDViewer's (`components/SettingsTabs.tsx`: Folders, Updates). The Workbench adds Appearance and Shortcuts, each plugin its own tabs; a new setting goes into its owner's tab
  - Status bar: the workbench's, one for the window (`Shell`'s `status`: pinned or auto-hiding, `statusBarPinned` in the store). Surfaces and panes put `StatusItem`s into it with `ShellStatus` while shown: the reader's `DocumentStatus` (from `DocumentGroups`: the focused document's path, size, age, words, reading time), the journal's index state and Revoke session access

- **Smooth scrolling**: `useSmoothWheelScroll` (`@lambda-house/ui`) - velocity-based wheel scrolling shared by the document, file panel, search and TOC

- **Commands** (`src/utils/commands.ts`): `buildMenu` is the one list of commands, assembled from MDViewer's own, the reader's (`readerCommands`), the journal's (`journalCommands`) and the workbench's (`layoutCommands`: split/close the focused pane, F6 between panes, reset the layout; `zoomCommands`: the focused pane's zoom, the document's before any pane had the focus; `windowCommands`: Command Palette, Settings, Dark/Light Theme, Pin Status Bar, whose ids the top bar's buttons look up for their tooltips). A command with a `surface` works only while that surface is shown (`commandForKey(…, surface)`, the menu disables it, the palette leaves it out); the store keeps the shown `surface`. The focused pane is the workbench's (`focusedPane()`, set by every `LayoutView` on a pointer press or focus inside a leaf, kept-alive panes included; it follows a layout's current leaf when its owner moves it), and it carries the focus line: a 2 px accent line on top of its header, the workbench's one rule. A button's tooltip names its command's key with `useCommandTitle(id, label)` (the Workbench's menu), so a key is written in one place. Ctrl+\ is the reader's Split Document. The rest: (label, shortcut, `enabled`/`checked`, `run`; the types and `commandForKey`/`formatShortcut` are `@lambda-house/workbench`'s, typed with `CommandContext`: `AppState & { reader: ReaderState }`; the main menu reads it with `useCommandContext`, the native menu with `commandContext()`; document commands act on the focused group). The menu renders it, the command palette lists it (through `appMenu`, set in `App.tsx`; `palette: false` keeps a command out), the native menu's events run it by id (`utils/nativeMenu.test.ts` fails if an item in `main.rs` has no command) and the `Workbench`'s key handler matches key presses against it (a key of a command on another surface does nothing), so a new command or shortcut goes there, not into either of them. `run` must be safe when `enabled` is false (shortcuts don't check it)

- **Markdown Processing** (`packages/reader/src/markdown.ts`, imported from `@lambda-house/reader`, like the file kinds, `resolveLinkPath`, find's `search.ts`, scroll anchoring and the editor registry):
  - markdown-it with `html: false` (raw HTML is escaped; every custom renderer rule must escape what it emits with `escapeHtml`)
  - Shiki for syntax highlighting (15+ languages)
  - Mermaid for diagrams with unique ID generation per render
  - HeadingIdGenerator for automatic anchor links
  - `renderFile` dispatches by type (`getFileKind` in the reader's `files.ts`): markdown, fb2 (converted via `fb2.ts`), code (one highlighted fence), plain text
  - Local images get their URL from `setImageUrl`, which `main.tsx` points at `convertFileSrc(path, 'localfile')`. Mermaid's `secure` list keeps diagrams from setting `themeCSS`/fonts (a `url()` there would fetch without the "Load images" consent)
  - Block elements carry `data-line` (0-based source line, frontmatter included) to map search results to the rendered DOM

### Backend (src-tauri/)

Rust backend provides Tauri commands:
- `scan_directories` - Recursive file discovery (markdown, plus other text files with `includeTextFiles`; extension lists mirrored in `packages/reader/src/files.ts`)
- `read_file` / `write_file` - File I/O; `read_file` decodes UTF-16 BOM and XML-declared encodings, `write_file` encodes back the same way (refuses unknown encodings) and replaces the file atomically (temp file + rename, `atomic_write`)
- `pick_directory` / `pick_files` / `export_file` - Native folder picker, file picker (Open File) and save dialog, opened from Rust (the JS dialog plugin isn't exposed)
- `get_file_info` - File metadata
- `start_watching` / `stop_watching` - File system watching (one event per change; `node_modules`/`target`/`.git` ignored). The frontend debounces rescans (300ms, no overlapping scans), `setFiles` reuses unchanged tree nodes, and open documents whose file name changed are reloaded unless dirty (`the reader's `reloadChangedDocuments`, called by the watcher in `App.tsx`)
- `read_history` / `append_to_history` / `clear_history` - `history/history.md` in the config dir, capped at 1000 entries, writes serialized
- `adopt_session_access` - One-time migration of a session saved before the access list existed
- `open_external` - Opens http/https/mailto links in the default browser (opener plugin, Rust-side only)
- `localfile://` protocol - Serves images referenced by documents (`convertFileSrc(path, 'localfile')` in the frontend)

Security: an allowlist (`Access` / `AccessState` in main.rs, persisted to `access.json` in the config dir). Paths are added only from Rust on user actions: the folder and file pickers, drag & drop (`on_window_event`), command-line / single-instance launch paths. Every command resolves its path to a `Target` (as named, and canonicalized with `dunce`) and checks it with `AccessState::check(target, Use::...)`: documents need to be an opened file or a viewable file inside an opened folder, listing/watching needs an opened folder, `localfile://` serves only images. A symlink inside an opened folder passes when its real target fits the use (`Use::fits_target`); paths with `..` only count as their real location. Never grant access to an arbitrary path passed from the webview. `follow_local_link` grants after the user confirms a native dialog; session memory opening grants only a Markdown file revalidated against the backend memory catalog under separate session and memory consent. 10MB limit for documents, 50MB for images. CSP in `tauri.conf.json`. A navigation guard plugin (`navigation_guard`) blocks any navigation away from the app's own pages; document link clicks are handled in `App.tsx` (anchors, `openExternal`, local files via `followLocalLink` then `openPath`). Updates: `tauri-plugin-updater`, Rust-only (`check_for_update`, `install_update`); the frontend shows `UpdateBanner` and blocks installing while tabs are dirty. Release builds need `TAURI_SIGNING_PRIVATE_KEY`/`_PASSWORD` because `bundle.createUpdaterArtifacts` is on. Remote images render as `span.remote-image` placeholders; `MarkdownViewer` swaps them in with `loadRemoteImages` when the `loadRemoteImages` setting or the per-document "Load images" allows it. Agent workspace (`src-tauri/src/agent.rs`, `@lambda-house/agents` with `src/agents.ts` as its host, `AgentPanel.tsx`): turned on by `enable_agent_workspace` after a native dialog, stored as `agent_workspace` in `access.json`. While on, `Access::can_open`/`can_stat` also allow `agent::is_agent_document` (markdown in fixed places under `~/.claude`, `~/.codex`, `~/.gemini`; extend `classify_rel` and its test together). Markdown includes Cursor's `.mdc` and `.cursorrules` (`is_markdown_file` / `isMarkdownFile`). `agent::Watch` (started by the `agent_workspace` scan, re-armed on every scan) emits `agent-files-changed`; the agents plugin debounces it and polls only when `watching` is false. `agent_workspace` scans those plus agent files in opened folders; `mark_read` / `read_snapshot` keep a copy per file in `read-state/` for the "changed since you read it" highlight (`diffContent` + `markChangedBlocks` on `data-line` blocks). Capabilities (`capabilities/default.json`) allow core defaults and window destruction for `main` and `memory-*` readers.

Tests: `cargo test` in `src-tauri` (unit tests at the bottom of main.rs and agent.rs). CI runs clippy, the Rust tests and `npm test`.

### Journal (sessions)

The Journal surface (the top bar's Documents/Journal switch) is `JournalView` from `@lambda-house/journal` (`packages/journal`): a layout of `journal-list` panes (search, folded filters with the directory map, results by folder) and `journal-detail` panes (a session's heading and tabs), each with the workbench's pane header (Sessions ⋯; Session: Resume in Live, close, ⋯) and its own zoom (Ctrl + wheel, kept in the journal store; the header shows it when it isn't 100 %). Actions inside a pane are ghost `Button`s; bordered text buttons only in its dialogs over one index snapshot, refreshed every 5 s while shown (`JournalView`'s `refreshInterval`). The host's `snapshotSince` (`sessions_snapshot_since`) sends a snapshot only when what it shows changed (its `stamp`, kept in the journal store and forgotten on revoke). A click in a list shows the session in the detail pane focused last; Mod+click or the row menu's "Open to the side" opens another detail pane beside it. `src/journal.ts` makes its store (`createJournalStore`, key `mdviewer-journal`: the layout, each list's filters, each pane's session and tab) and its host (`JournalHost`: the IPC contract, by command name; MDViewer has every optional part: remote context, Codex control, agent access; `src/journal.test.tsx` checks it). The package's `sessions.ts` has the types and the pure accounting/search helpers. `src-tauri/src/sessions.rs` is the incremental Codex/Claude JSONL index, backed by `session_db.rs` (SQLx SQLite) and versioned checkpoints plus paged events. All database work runs on blocking workers. Checkpoints and events commit atomically; usage deduplication survives restart. Do not discard history when directory enumeration fails. `session_memory.rs` discovers fixed memory locations and revalidates each read; `Access.session_memories` is a separate native grant. Human forks are not child agents. Directory history, role and last-activity filters are defined in the journal's `sessions.ts` (`filterSessions`); `session_commands.rs` holds the opt-in access gate, read-only remote contexts and existing-daemon Codex controls. `Access.session_workspace` is independent of `agent_workspace`. Do not grant general document reads for transcripts. Keep credentials in process memory, never in the Zustand store or exports. Usage records must be deduplicated; cache/reasoning are subsets of input/output, not extra totals. Summaries exclude activity bodies, and details load on selection. Status inferred from files must not be presented as verified process liveness. Tests cover parser accounting, partial/truncated files, hierarchy and the UI access/control paths. `examples/session_snapshot.rs` extracts real local metadata using the same index.

Memory reader windows use a validated `memoryDocument` URL and isolated, read-only inherited preferences (`documentWindowStorage` for the app store, `documentWindowReaderStorage` for the reader: its settings and zoom, no tabs). They do not overwrite the main workspace, own its watchers or consume its launch paths. Native menu events target the focused window.

### Session analysis MCP

`session_analysis.rs` is the bounded read-only query layer; `session_mcp.rs` implements MCP lifecycle, the app-owned Unix socket and the `--mcp` stdio bridge. The bridge branch in `main` must run before AppKit/Tauri initialization and never open SQLite. `session_analysis_commands.rs` owns the per-process native-confirmed grant and background ingestion using the same `SessionState.index` as the UI. Revocation closes connected sockets; keep grant→index lock order. The journal's `AgentAccess` shows scope, clients, query audit and evidence navigation. Never infer inner exec execution, skill success, historical definition versions or per-tool tokens from references. `examples/analysis_host.rs` and `scripts/validate-session-mcp.mjs` exercise the production query/transport with the official MCP client SDK and explicit fixture paths. See `docs/SESSION_ANALYSIS_MCP.md` for semantics and remaining limits.

### Path Alias

TypeScript path alias `@/*` maps to `src/*` (configured in tsconfig.json and vite.config.ts).

### Shared packages (`packages/`)

npm workspaces (`@lambda-house/tokens`, `ui`, `workbench`, `reader`, `journal`, `agents`) shared with Agent MCR, which keeps a `git subtree` copy. The plan is the shared UI spec in `20261122_ui-concept.md`; the sync commands and rules are in `packages/README.md`.

- Shared code imports nothing from the app: no `src/`, no `@/`, no `@tauri-apps/*`, no app store. It gets what it needs through host interfaces the app passes in. `packages/layers.test.ts` enforces the layer order and the allowed libraries; `tsc -p packages` type-checks without the app's alias.
- Shared changes are made here first; Agent MCR merges them in. A change made in Agent MCR comes back as a patch.
- Colours, spacing, radii and type sizes come from `@lambda-house/tokens` (`packages/tokens/tokens.css`, loaded first in `main.tsx`). Every colour a rule uses is a variable: shared ones from the tokens, a feature's from its own `:root` block (the reader's `--syntax-*`, `--find-match-bg` and document type sizes at the top of `reader.css`; the app's at the top of `index.css`). The reader's styles are all in `reader.css`, so `index.css` holds only MDViewer's own parts. Only the tokens' names exist (`--canvas`, `--text`, `--line`, `--accent`, `--fs-13`, `--r-md`, …): the old aliases (`--surface-bg`, `--text-primary`, …) are gone, and `packages/styles.test.ts` fails on a variable no stylesheet defines.
- A pane whose content is expensive to recreate (terminal, editor, rendered document) is `keepAlive`.
- `@lambda-house/ui/ui.css` loads after the tokens, then `workbench.css`, and starts with the elements' base look (resets, scrollbars, selection, the focus ring, button/input/link resets) in `@layer base`, so every other rule wins over it; then `@lambda-house/reader/reader.css`, `@lambda-house/journal/journal.css` and `@lambda-house/agents/agents.css`, then `index.css`. App CSS never targets `ui-*` classes: a control that needs another look gets a prop. App element rules that could reach a shared control skip it without changing their weight: `.session-cockpit button:where(:not([class^="ui-"],[class*=" ui-"]))` (in `journal.css`). Menus render in place, so a descendant rule over a menu's owner (`.x button`) reaches its items too: use a child combinator or the same exclusion.

## Configuration

There is no config file. UI settings, folders, tabs and workspaces live in localStorage (Zustand persist). The backend's config dir (`dirs::config_dir()/mdviewer`) holds `access.json`, `history/history.md`, `read-state/` (agent workspace), and `sessions/index.sqlite` with its SQLite sidecars. The `sessions-preview` feature uses the separate `mdviewer-sessions-preview` folder. Revoking session access clears the SQLite index and disables memory access.

## Key Patterns

- React functional components with hooks (no class components except ErrorBoundary)
- CSS custom properties for theming: dark by default, light overrides under `:root[data-theme='light']`; Shiki emits both themes as `--shiki-dark` / `--shiki-light` variables
- Zustand actions return `{ success: boolean; error?: string }` for operations that can fail
- Scroll handlers debounced at 50ms
- Mermaid renders lazily with strict security level
